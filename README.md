# LinQ Safety Guard: Интеллектуальный сервис контроля промышленной безопасности

> **Проверенный статус CV и команды запуска:** [CV_HANDOFF.md](CV_HANDOFF.md).
> Модели и подтверждённые аппаратные замеры в репозитории отсутствуют. Ниже описана
> целевая архитектура; наличие кода/демо не означает подтверждённую работу на TPU.
> `python run.py` запускает API, `python run_worker.py` — отдельный CV-процесс.

Комплексная система компьютерного зрения и видеоаналитики для предупреждения нарушений охраны труда и техники безопасности на производстве с аппаратным ускорением на российских ИИ-ускорителях **LinQ TPU (платформа H1M)**.

Разработано в рамках хакатона **«Открой Моспром»** (кейс LinQ).

---

## 📌 Архитектурные возможности

* **Аппаратное ускорение на отечественных чипах**: интеграция с LinQ TPU через нативный драйвер `pytpu` со статическим квантованием графа (FP19 / INT8).
* **Модульный Hardware Abstraction Layer (HAL)**: прозрачное переключение между LinQ TPU и локальным фоллбэком на ONNXRuntime/CPU.
* **Отслеживание динамики во времени**: трекинг перемещения людей и техники на базе алгоритма ByteTrack (присвоение `Track ID` и расчет векторов скорости).
* **Движок правил промышленной безопасности (Safety Rules Engine)**:
  * Детекция нарушения периметра и опасных зон с произвольными полигонами (Point-in-Polygon на базе Shapely);
  * Предупреждение об опасном сближении людей с подвижной техникой (погрузчики, кары);
  * Фиксация падения человека и длительной неподвижности (анализ изменения геометрии и вектора ускорения);
  * Контроль обязательного ношения СИЗ (каски, жилеты).
* **Подавление ложных тревог и дедупликация спама**:
  * *Debounce*: фиксация события только при устойчивом нарушении в течение $N$ кадров;
  * *Cooldown*: одно длящееся нарушение порождает ровно одно системное оповещение, а не лавину сообщений на каждом кадре.
  * Повторные фиксации одного типа нарушения на той же камере в течение 5 минут обновляют существующую открытую запись журнала и исходное сообщение Telegram (включая standalone-режим); после закрытия события или паузы более 5 минут создаётся новый инцидент.
* **Расширение каналов оповещения**: IT-команда клиента может подключить корпоративный мессенджер Python-адаптером, наследующим `BaseMessengerAdapter`, без изменений ядра.
* **Операторский веб-интерфейс**:
  * Real-time видеомониторинг с оверлеем боксов и цветовой индикацией зон;
  * Интерактивный редактор полигонов зон прямо на кадре камеры;
  * Журнал инцидентов с доказательной базой (фото/видео фрагмент, таймштамп, статус верификации);
  * Аналитический дашборд статистики по сменам и цехам.

## 📂 Структура репозитория

```text
├── configs/               # Конфигурационные файлы зон и сервиса
├── models/                # Артефакты нейросетей (.onnx и скомпилированные .tpu)
├── linq_tools/            # Утилиты компиляции, квантования и бенчмаркинга под LinQ TPU
├── engine/                # Ядро компьютерного зрения (CV Engine)
│   ├── inference/         # Слой абстракции инференса (LinQ TPU / ONNX CPU)
│   ├── tracking/          # Трекер объектов (ByteTrack)
│   ├── rules/             # Правила ТБ (зоны, падения, сближение, СИЗ)
│   └── deduplication/     # Защита от дублей и подавление ложных тревог
├── app/                   # Бэкенд на FastAPI (REST API, WebSockets, БД)
│   └── routes/            # Эндпоинты управления камерами, событиями и аналитикой
├── frontend/              # Веб-интерфейс диспетчера и службы охраны труда
└── storage/               # Локальная база данных, снапшоты нарушений и демо-видео
```

## Интеграция корпоративного мессенджера

Создайте Python-модуль и унаследуйте адаптер от `BaseMessengerAdapter`. Реализуйте отправку нового инцидента и обновление уже отправленного сообщения: последнее используется при повторной фиксации нарушения и смене статуса.

```python
import os
from app.services.notifications import BaseMessengerAdapter


class CompanyMessenger(BaseMessengerAdapter):
    channel = "company_chat"

    def __init__(self, manager):
        self.endpoint = os.environ["COMPANY_MESSENGER_ENDPOINT"]
        self.api_key = os.environ["COMPANY_MESSENGER_API_KEY"]

    def send_alert(self, subscriber, event, snapshot_path=None):
        # Вызовите API мессенджера и верните (ID сообщения, тип сообщения).
        # subscriber["chat_id"] — ID чата, event — данные инцидента.
        raise NotImplementedError("Реализуйте отправку сообщения через API мессенджера")

    def update_alert(self, delivery, event):
        # Обновите delivery["message_id"], не отправляя новое оповещение.
        raise NotImplementedError("Реализуйте обновление сообщения через API мессенджера")


def create_adapter(manager):
    adapter = CompanyMessenger(manager)
    manager.store.upsert_subscriber(
        adapter.channel, "safety-team", "Служба ОТ и ТБ", "channel"
    )
    return adapter
```

Установите пакет расширения в окружение backend и укажите фабрику в `.env`:

```dotenv
LINQ_MESSENGER_ADAPTERS=company_plugin:create_adapter
COMPANY_MESSENGER_ENDPOINT=https://messenger.example/api
COMPANY_MESSENGER_API_KEY=<секрет из хранилища секретов>
```

Можно указать несколько фабрик через запятую. Каждая фабрика получает `NotificationManager` и возвращает экземпляр `BaseMessengerAdapter`. Адаптеры запускаются и останавливаются вместе с backend; общий менеджер применяет фильтр важности, ведёт журнал доставок и передаёт обновления. Используйте `manager.store.upsert_subscriber(...)` для регистрации получателей. Плагин выполняется с правами backend: подключайте только доверенный код, а ключи храните в переменных окружения, не в репозитории.

## 🚀 Быстрый старт

### 1. Установка зависимостей
```bash
python -m venv venv
# Linux / macOS:
source venv/bin/activate
# Windows:
venv\Scripts\activate

pip install -r requirements.txt
```

### 2. Настройка окружения
Скопируйте пример конфигурации:
```bash
cp .env.example .env
```

### 3. Запуск веб-сервиса
```bash
uvicorn app.main:app --host 0.0.0.0 --port 8000 --reload
```
Интерфейс доступен по адресу: `http://localhost:8000`  
Документация Swagger/OpenAPI: `http://localhost:8000/docs`

## 🛠️ Специфика платформы LinQ TPU
* Аппаратный профиль: `TPU_H1M` (платформа `h1m`).
* Пайплайн компиляции: `PyTorch -> ONNX (статичный shape 640x640) -> tpu_framework (квантование + компиляция) -> .tpu`.
* Рантайм инференса: библиотека `pytpu` (`/dev/tpu*`).
