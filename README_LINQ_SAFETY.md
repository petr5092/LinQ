# Контроль техники безопасности по видео на LinQ TPU

Сервис принимает видео с камер, находит нарушения нейросетью и сразу присылает оповещение
с кадром-доказательством в веб-интерфейс. Хакатон «Открой Моспром», кейс LinQ.

## Запуск за минуту (без модели и без TPU)

```bash
pip install -r requirements-linq-safety.txt
python run.py            # демо: две синтетические камеры со сценарием нарушений
# открыть http://localhost:8000
python -m unittest discover -s tests   # тесты
```

Веб-панель по умолчанию доступна только на этом компьютере (`127.0.0.1`). Для запуска
из корня репозитория скопируйте `linq-safety.env.example` в `.env` только если файл
`.env` ещё не создан, затем заполните нужные токены. Сервис читает `.env` из корня проекта.

Демо работает на разметке синтетической сцены (`--backend mock`). Это нужно, чтобы проверить
всю цепочку (трекинг, правила, журнал, интерфейс) до того, как модель собрана для TPU.
Цифры производительности в этом режиме **не показательны**.

## Запуск с настоящей моделью

```bash
pip install onnxruntime opencv-python-headless
python run.py --backend onnx --model best.onnx --source cam.mp4 --source rtsp://host/stream
python run.py --backend linq --model program.tpu --source cam.mp4     # на ВМ с LinQ
python bench.py --backend linq --model program.tpu --frames 300       # замеры для защиты
```

Ожидаемая модель: YOLOv8-стиля, выход `(1, 4+nc, N)` или `(1, N, 4+nc)` без objectness.
Порядок классов задайте в `app/config.py` (`CLASS_NAMES`) или флагом `--classes`.
По умолчанию: `person, helmet, no_helmet, vest, no_vest, phone`. Если у вашей модели нет классов
`no_*`, поставьте в `RULE_PARAMS` для `no_helmet`/`no_vest` режим `"mode": "absence"`
(нарушение — когда каски/жилета в области головы/торса нет).

## Уведомления в Telegram и VK

Бот работает через long polling: публичный адрес и webhook не нужны. Токены хранятся в `.env`
(образец — `linq-safety.env.example`), в код и git они не попадают.

**Telegram.** Создайте бота у @BotFather (`/newbot`), токен — в `LINQ_TG_TOKEN`, перезапустите `run.py`.
На вкладке «Уведомления» нажмите «Добавить в группу» (ссылка вида `t.me/<бот>?startgroup=linq`),
выберите чат смены. Как только бота добавили, чат фиксируется сам, в нём появляется приветствие.
Дальше в этот чат приходят нарушения: кадр с выделенным человеком, камера, зона, время, тип и кнопки
**Подтвердить / Ложное / Принял, иду**. Нажатие меняет статус в журнале (с именем нажавшего и временем),
подпись сообщения обновляется во всех чатах. Команды в чате: `/start`, `/stop`, `/status` (сводка за сутки),
`/level all|medium|high|critical` (порог важности отдельно для каждого чата).
Для канала бота нужно сделать администратором с правом публикации.

**VK.** Сообщество → «Управление» → «Работа с API» → ключ с правами «сообщения» и «фотографии»
(`LINQ_VK_TOKEN`, `LINQ_VK_GROUP_ID`). Включите сообщения сообщества, Bots Long Poll API
(события `message_new`, `message_event`) и «Разрешать добавлять сообщество в беседы».
Добавьте сообщество в беседу: чат зафиксируется сам. Чтобы бот видел команды, сделайте его администратором беседы.
Оповещение приходит с фото и inline-кнопками; в VK сообщение с фото после нажатия не переписывается
(ответ на кнопку показывается всплывающим уведомлением, статус виден в панели).

Надёжность доставки: 3 попытки с паузой, учёт `retry_after` Telegram, чат автоматически
отключается, если бота удалили или заблокировали. Каждая доставка пишется в `data/notify.db`
(ok/ошибка/задержка) и видна в дашборде.

Время реакции — от момента тревоги до нажатия кнопки (в чате или в панели).

## Как подключить LinQ TPU

Инференс идёт по маршруту из «Процедуры подготовки…»: ONNX → SDK (квантование, компиляция) →
Программа для TPU → вызов через Python API. Препроцессинг и постпроцессинг уже готовы
(`letterbox`, `decode_yolo` в `app/detector.py`). Осталось:

1. Собрать Программу для TPU из вашей ONNX-модели по `tpu_framework.pdf`. **Сделайте это первым делом**:
   если какие-то операции модели не поддерживаются, лучше узнать сразу и выбрать другую модель.
2. `cp linq_adapter_template.py linq_adapter.py` и дописать три места с `TODO`
   по примеру из `usage_example_python_api.zip`. В шаблоне нет реальных вызовов API:
   их описание есть только в материалах организаторов.
3. Запустить `python run.py --backend linq --model program.tpu` на ВМ с ускорителем
   (подключение: OpenVPN, затем Jupyter `hackathon.lin-q.ru`).

## Как это устроено

```
источник -> детектор (TPU) -> трекер -> правила -> движок -> журнал + SSE + кадр
 video/rtsp   person, helmet,   ID у     плагины   подтверждение   SQLite  веб-
 /папка       vest, phone…      человека           и дедупликация          интерфейс
```

Только детектор нагружает ускоритель, остальное идёт на CPU. Один детектор делят все камеры.

| Файл | Что делает |
|---|---|
| `app/detector.py` | препроцессинг, постпроцессинг, ONNX/LinQ/mock-детекторы |
| `app/tracker.py` | IoU-трекер, устойчивый к падению (резкой смене формы рамки) |
| `app/rules.py` | правила-плагины: падение, опасная зона, каска, жилет, телефон |
| `app/engine.py` | подтверждение по времени и подавление повторов |
| `app/store.py` | журнал (SQLite) и зоны (JSON) |
| `app/server.py` | веб-сервер: REST, SSE, MJPEG, CSV, `/metrics` |
| `app/notify/` | боты Telegram и VK, подписчики, рассылка с повторами, обновление сообщений по статусу |
| `frontend/index.html` | интерфейс: мониторинг, журнал, статистика, разметка зон |
| `bench.py` | замеры скорости и оценка числа камер на одном ускорителе |

### Как избегаем ложных тревог
- Нарушение должно длиться `confirm_s` секунд подряд (по умолчанию 1,5–2 с), одиночный кадр ничего не вызывает.
- Одно нарушение одного человека — одно оповещение, пока оно не прекратится на `gap_s` (2 с).
- Если человека на время закрыли и трек получил новый ID, повтор подавляется (`dedup_s`).
- Слишком мелких людей (ниже 15% высоты кадра) на СИЗ не проверяем.
- Оператор отмечает событие: подтвердить / ложное / передать мастеру. Доля ложных видна на вкладке «Статистика».

### Добавить новый тип нарушения
В `app/rules.py` напишите класс с `@register`, `type`, `label`, `severity` и методом `evaluate(ctx)`,
который возвращает список `Candidate`. Больше ничего менять не нужно: подтверждение, журнал,
фильтры, статистика и интерфейс подхватят его сами. Параметры — в `RULE_PARAMS`.
Заготовки для следующих сценариев кейса: бег (скорость центра трека в долях роста), курение
(класс `cigarette/smoke` в модели + правило как у телефона), работа на высоте без привязи
(зона «высота» + класс `harness`).

## Что реализовано из требований кейса

| Требование | Где |
|---|---|
| Приём видеопотоков и наборов кадров | `app/sources.py`: файл, RTSP, папка изображений |
| Распознавание нейросетью | `app/detector.py` (YOLO, ONNX → LinQ) |
| Оповещение с кадром, камерой, временем, типом | лента на вкладке «Мониторинг», SSE и звук для критичных |
| Подавление повторов | `app/engine.py`, тесты в `tests/test_core.py` |
| Журнал с фильтрами по типу, камере, зоне, времени | вкладка «Журнал», `/api/events`, выгрузка CSV |
| Инференс на LinQ с замерами | `bench.py`, показатели в шапке интерфейса |
| Разметка зон на кадре (желательно) | кнопка «Разметить опасную зону» |
| Дашборд со статистикой (желательно) | вкладка «Статистика» |
| Подтверждение/отклонение оператором (желательно) | кнопки в ленте |
| Несколько потоков (желательно) | `--source` можно повторять |

## Ограничения (честно, для защиты)
- Качество определяется моделью: проект даёт конвейер и правила, а не обученную нейросеть.
- Правило падения работает по форме и неподвижности рамки человека; сидящий или присевший работник может дать срабатывание, поэтому порог `aspect` и `still_s` настраиваются.
- Демо-сцена синтетическая; на реальном видео параметры правил нужно подбирать.
- Сервер на стандартной библиотеке рассчитан на единицы камер и десятки зрителей, для большего ставьте за nginx или переходите на FastAPI.
- Авторизации нет: сервис рассчитан на закрытую сеть предприятия. Любой участник чата может нажать кнопку статуса.
- Боты проверены только на имитации API Telegram и VK (тесты `tests/test_notify.py`), на живых серверах не запускались: проверьте на своём токене.
- Для рассылки машине с сервисом нужен выход в интернет к `api.telegram.org` / `api.vk.com` (или прокси через `HTTPS_PROXY`). ВМ с TPU за OpenVPN может его не иметь: тогда запускайте панель с ботами на своём компьютере, а замеры TPU делайте `bench.py` на ВМ.
