# AGENTS.md — Архитектурный контракт и реестр решений проекта LenQsec

Данный документ фиксирует все ключевые архитектурные, инженерные и продуктовые решения, принятые в рамках проекта **LenQsec** (хакатон «Открой Моспром», кейс LinQ). Он является единым источником правды для разработчиков и ИИ-ассистентов при работе с кодовой базой репозитория.

---

## 1. Контекст проекта и бизнес-цель

* **Продукт**: **LenQsec** — Интеллектуальный программно-аппаратный комплекс видеоаналитики, тепловизионного контроля и оперативного оповещения о нарушениях техники безопасности и охраны труда (ОТ и ТБ) на промышленных объектах.
* **Ключевой технологический стек**: Российские аппаратные ИИ-ускорители **LinQ TPU (архитектура TPU_H1M)**.
* **Главный критерий оценки**: Подтвержденный запуск инференса нейросетей на отечественном чипе LinQ с объективными замерами быстродействия (FPS и Latency в миллисекундах), доказанный технологический суверенитет, надежность контроля (минимум ложных тревог) и комплексность аналитики (включая тепловизионный мониторинг).

---

## 2. Аппаратная платформа LinQ TPU

1. **Аппаратный профиль**:
   * Чип: специализированный тензорный процессор LinQ, профиль `TPU_H1M` (платформа `h1m`).
   * Арифметика: поддержка вычислений с плавающей точкой **FP19** (библиотека `fp19_exp`) и целочисленного квантования **INT8**.
2. **Пайплайн подготовки нейросетевых моделей**:
   $$\text{PyTorch / YOLO (.pt)} \longrightarrow \text{ONNX (статичный shape [1, 3, 640, 640])} \xrightarrow[\text{tpu_framework}]{\text{Оптимизация + Квантование (O1/O5)}} \text{Программа LinQ (.tpu)}$$
   * **Важно**: динамические размерности (`dynamic_axes`) чипом **не поддерживаются**. Входной тензор обязан иметь фиксированный размер.
3. **Рантайм инференса**:
   * Нативный Python API `pytpu` (`tpu.Device.open()`, `tpu_device.load()`, `tpu_program.inference()`).
   * Реализация официального жизненного цикла в `linq_adapter.py`: предпочтение методу `sync()`, совместимость с методом `run()`.
4. **Стенд организаторов**:
   * Доступ через OpenVPN: сервер `83.220.57.3:1194`, подсеть `10.0.114.0/24`.
   * Jupyter Notebook: `http://hackathon.lin-q.ru/`.
   * Брокер очередей RabbitMQ: `10.0.114.30:5672`.

## 3. Архитектура системы LenQsec: Разделение контуров

Система разделена на два **строго изолированных сервиса/процесса**:

```text
[ Камеры / Видеопотоки / Тепловизоры ] 
                 │
                 ▼
┌─────────────────────────────────────────┐
│     CV-воркер (Inference Engine)        │ ◄─── CPU / TPU-bound
│  • Чтение видео (OpenCV / RTSP)         │
│  • LinQ TPU Driver (pytpu)              │
│  • Трекинг во времени (ByteTrack)       │
│  • Движок правил (Shapely)              │
│  • Дедупликация (Debounce / Cooldown)   │
│  • Outbox дисковая очередь              │
└─────────────────────────────────────────┘
                 │ (HTTP POST / REST API: только подтвержденные инциденты + снапшот)
                 ▼
┌─────────────────────────────────────────┐
│     Web-сервис LenQsec (FastAPI)        │ ◄─── I/O-bound
│  • База данных (PostgreSQL / SQLite)    │
│  • Радиометрический контур тепловизоров │
│  • Управление камерами, зонами и СКУД   │
│  • S3 / Local Storage Provider          │
│  • WebSocket Broadcast                  │
│  • Служба уведомлений Telegram & Corp   │
└─────────────────────────────────────────┘
                 │
                 ▼
┌─────────────────────────────────────────┐
│     LenQsec Web Dashboard               │ ◄─── React 19 / TypeScript
│  • Живые видеопотоки и термограммы      │
│  • Интерактивный редактор полигонов     │
│  • Журнал инцидентов и доказательств    │
│  • Сменная аналитика и экспорт CSV      │
└─────────────────────────────────────────┘
```

* **Обоснование изоляции**: декодирование видеопотоков, радиометрический расчет и нейросетевой инференс не должны блокировать асинхронный цикл веб-сервера и реактивность интерфейса оператора.

## 4. Стек технологий

1. **Python 3.12 — основной язык серверного ядра и CV**:
   * Бэкенд: **FastAPI**, **Uvicorn**, **Pydantic v2**, **SQLAlchemy**, **Alembic**.
   * CV и геометрия: **OpenCV**, **NumPy**, **ByteTrack**, **Shapely**.
   * Инференс: **pytpu** (LinQ TPU), **onnxruntime** (CPU fallback).
2. **React 19 & TypeScript — фронтенд оператора**:
   * UI-фреймворк: **React 19**, **TypeScript**, **Vite**, **Tailwind CSS**.
   * Иконки и компоненты: **Lucide React**, **Base UI**, дизайн-система **HR Vision**.
3. **C++ — целевая архитектура масштабирования для Edge**:
   * Для защиты проекта и демонстрации жюри: ссылаемся на официальный `usage_example_cpp_api_resnet50_opencv` от LinQ.
   * Позиционирование: промышленный вариант поставки решения на встраиваемые Edge-коробки цеха строится на C++ для достижения честного Zero-Copy и задержки менее 15 мс без накладных расходов интерпретатора.

## 5. Слой абстракции над железом (Hardware Abstraction Layer)

Для обеспечения непрерывности разработки и тестирования вне контура VPN реализован HAL (`BaseInferenceEngine`):
* `LinQTPUEngine`: промышленный инференс на стенде LinQ через драйвер `pytpu`.
* `LocalONNXEngine`: локальный фоллбэк на базе `onnxruntime` (CPU) для быстрой локальной отладки.
* `MockEngine`: программный эмулятор для CI/CD и модульных тестов без весов модели.
* Переключение осуществляется одной переменной в `.env`: `INFERENCE_BACKEND=LINQ_TPU`, `ONNX_CPU` или `MOCK`.

## 6. Движок правил и сценарии нарушений

* **Полигональные опасные зоны**: проверка попадания нижней опорной точки человека (стоп) в произвольный полигон, размеченный оператором (`Shapely.polygon.contains`).
* **Контроль СИЗ**: проверка наличия каски (`helmet`) и сигнального жилета (`vest`) на обнаруженных силуэтах персонала.
* **Опасное сближение с техникой**: мониторинг евклидовой дистанции между треками человека (`person`) и погрузчика (`forklift`).
* **Падение и неподвижность**: детекция резкого изменения соотношения сторон рамки ($w/h > 1.2$, человек лежит) в сочетании с околонулевой скоростью трека более 2 секунд.
* **Тепловой перегрев оборудования**: зональный анализ радиометрических температур в °C с фиксацией инцидентов `environment` при превышении заданного порога.

## 7. Дедупликация и подавление ложных тревог (Anti-Spam)

Решение критической боли заказчиков промышленных систем:
1. **Debounce (подтверждение длительностью)**: нарушение регистрируется, только если модель стабильно видит его $N$ кадров подряд (по умолчанию 15 кадров / 1.5 секунды), что исключает реакцию на единичные артефакты детекции.
2. **Cooldown по `Track ID`**: пока конкретный рабочий находится в зоне нарушения, система создает **ровно одно** оповещение. Повторная отправка блокируется на заданный таймаут (по умолчанию 300 секунд).
3. **5-минутное слияние инцидентов**: повторные фиксации того же типа нарушения на камере объединяются в существующую открытую запись БД и исходное сообщение в Telegram/мессенджерах.
4. **Outbox Pattern**: при сбое сетевого соединения инциденты и снимки сохраняются в локальную дисковую очередь `data/offline_outbox` и гарантированно доставляются при восстановлении связи.

## 8. Радиометрический тепловизионный контур

* **Приём кадров**: эндпоинт `POST /api/v1/thermal/cameras/{camera_id}/frame` принимает двумерные матрицы температур в °C.
* **Конфигурация**: файл `configs/thermal_cameras.yaml` определяет зоны контроля, пороговые значения `max_temperature_c` и температуры сброса `clear_temperature_c`.
* **Генерация термограммы**: динамическое колорирование матрицы (палитра Inferno / Jet) с нормировкой по текущему диапазону температур кадра.
* **Трансляция**: прямая отдача актуального JPEG через `/api/v1/thermal/cameras/{camera_id}/heatmap.jpg` и интеграция с общим сервисом `CameraHub`.

---

## 9. Хранение доказательной базы инцидентов (Storage Layer)

* **Категорический запрет**: запрещено хранить полноразмерные изображения как BLOB или Base64 в реляционной базе данных.
* **Модульная архитектура хранения (`BaseStorageProvider`)**:
  * `LocalStorageProvider`: локальный диск, автоматическое партиционирование папок по датам (`storage/snapshots/YYYY-MM-DD/inc_{uuid}_{camera}.jpg`), сжатие JPEG quality 80 (~100 КБ на кадр).
  * `S3StorageProvider`: поддержка объектных хранилищ по протоколу S3 (**MinIO**, **Yandex Cloud Object Storage**, AWS) с генерацией безопасных Presigned URLs.
* **База данных**: хранит только текстовые метаданные инцидента и относительный ключ/URL к снапшоту.
