# Руководство по интеграции радиометрических тепловизоров в LenQsec

Настоящее руководство описывает принципы работы, схему конфигурации, протоколы интеграции и процедуру калибровки радиометрических тепловизоров в платформе **LenQsec**.

---

## 1. Концепция тепловизионного контроля

В отличие от стандартных камер видимого диапазона (RGB), радиометрический тепловизор измеряет излучение в длинноволновом инфракрасном диапазоне (LWIR 8–14 мкм) и формирует **двумерную матрицу абсолютных температур в градусах Цельсия (°C)**.

В архитектуре **LenQsec** реализованы следующие принципы:
1. **Разделение телеметрии и визуализации**:
   * Для алгоритмов контроля порогов и принятия решений используются исходные численные значения в °C.
   * Для отображения оператору матрица динамически нормализуется по текущему диапазону $[T_{\min}, T_{\max}]$ кадра и окрашивается в псевдоцвета (палитра Inferno / Jet).
2. **Зональный мониторинг (ROI — Regions of Interest)**:
   * На тепловизор накладываются прямоугольные или полигональные зоны (например, «Подшипниковый узел», «Электрощитовая», «Корпус редуктора»).
   * Каждая зона имеет собственный порог предупреждения (`max_temperature_c`) и порог сброса тревоги (`clear_temperature_c`).
3. **Защита от ложных всплесков**:
   * Для фиксации тревоги требуется подтверждение превышения порога на минимальной площади (параметр `min_pixels`) в течение нескольких последовательных измерений (`confirm_frames`).

## 2. Конфигурация тепловизоров (`configs/thermal_cameras.yaml`)

Файл конфигурации определяет параметры камер и контрольных зон:

```yaml
cameras:
  - id: "THERMAL-01"
    name: "Тепловизор главного привода конвейера"
    site_id: "north"
    workshop: "Цех № 1"
    zones:
      - id: "motor_bearing"
        name: "Подшипниковый узел"
        # Координаты прямоугольника: [x1, y1, x2, y2] в долях кадра от 0.0 до 1.0
        roi: [0.35, 0.40, 0.65, 0.70]
        # Порог срабатывания тревоги (°C)
        max_temperature_c: 75.0
        # Температура сброса тревоги (°C)
        clear_temperature_c: 68.0
        # Минимальное количество пикселей с превышением
        min_pixels: 4
        # Количество подтверждающих кадров
        confirm_frames: 3

      - id: "gearbox"
        name: "Корпус редуктора"
        roi: [0.10, 0.20, 0.35, 0.50]
        max_temperature_c: 85.0
        clear_temperature_c: 78.0
        min_pixels: 5
        confirm_frames: 3
```

## 3. Протокол передачи кадров (Ingestion API)

Адаптер производителя камеры регулярно отправляет сырые матрицы температур на эндпоинт бэкенда LenQsec:

`POST /api/v1/thermal/cameras/{camera_id}/frame`

### Пример отправки кадра на Python:
```python
import numpy as np
import requests

# Пример: получение матрицы 120x160 из SDK камеры в °C
temperatures_celsius = np.array([...], dtype=np.float32)

payload = {
    "captured_at": "2026-10-25T14:00:00Z",
    "temperatures": temperatures_celsius.tolist()
}

response = requests.post(
    "http://127.0.0.1:8000/api/v1/thermal/cameras/THERMAL-01/frame",
    json=payload,
    timeout=2.0
)
response.raise_for_status()
result = response.json()
print("Статус обработки:", result["status"])
```

## 4. Стриминг и отображение термограмм

Для обеспечения максимальной отзывчивости интерфейса оператора:
1. При обработке кадра бэкенд формирует JPEG-термограмму высокого качества.
2. Термограмма публикуется во внутренний `CameraHub`.
3. Операторский веб-интерфейс получает кадр напрямую по адресу:
   `http://localhost:8000/api/v1/thermal/cameras/{camera_id}/heatmap.jpg`
4. Если камера находится в аварийном состоянии, кадр автоматически маркируется в общем реестре инцидентов со стоп-кадром момента превышения порога.

### Запуск симуляции и проверки:
```powershell
.\.venv\Scripts\python.exe tools/replay_thermal_csv.py data/thermal/osf_sample/Beef_LR_38_20_30.csv --camera-id THERMAL-OSF-TEST --repeats 10 --interval 1
```
